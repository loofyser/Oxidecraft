# Handoff — starting M1

Written 2026-09-23, at the end of milestone M0.

**Where the project stands.** M0 ("foundations") is complete. The annotated tag `m0` marks the
milestone commit; a close-out wave of fixes landed on `main` right after it, and CI is green on all
seven jobs. `docs/STATE.md` carries the full evidence record.

**What M0 delivered**

| Area | State |
| --- | --- |
| Workspace | Eight crates (`oxide-proto`, `oxide-proto-v47`, `oxide-world`, `oxide-assets`, `oxide-render`, `oxide-game`, `oxide-launcher`, `oxide-client`), edition 2024, declared floor rust 1.85, committed `Cargo.lock` |
| Protocol | VarInt codec with golden vectors; length-prefixed framing with the 1.8 compression rules and hostile-input guards; handshake and status ping with a golden byte fixture |
| Assets | Hash-verified atomic store (SHA-1, temp-plus-rename, read-only objects, symlink refusal); piston-meta chain parsing; `fetch --verify` with single-instance locking and a disk-space precheck; jar extraction with an atomic manifest that never reads or extracts `.class` files |
| Renderer | wgpu window on Vulkan with the adapter and driver logged, a clear pass, and a frame counter that counts only presented frames |
| Automation | CI with seven jobs (format/lints/tests, release build, licences and advisories, MSRV at 1.85, Windows cross-check, crate graph, asset guard); `deny.toml`; the asset guard keeps every Mojang file type out of the repository |

**Evidence recorded in `docs/STATE.md`**

- CI: green on `main` at the close-out head, seven jobs.
- Real fetch from Mojang's endpoints: 726 transfers, 123,543,629 bytes on a cold run; a verify pass of
  722 objects with none mismatched and none missing; a second run downloads nothing.
- Window: NVIDIA T500 on Vulkan (driver 615.71.09), surface `Bgra8UnormSrgb` 1280x720, about 60 fps
  over 900 frames, title `Oxidecraft — 60 fps — NVIDIA T500`.
- Rig: a local offline-mode 1.8.9 server answers our own status ping (`1.8.9 — protocol 47 — 0/20
  players`) and the vanilla client reaches its title screen.

**Environment facts**

- CachyOS; Rust 1.95 with the workspace floor at 1.85; GNOME on Wayland with XWayland supplied by
  mutter (the 1.8.9 rig client needs it); Vulkan 1.4.357; Intel Iris Xe and NVIDIA T500.
- Two pins matter: `wgpu 26.0.1` and `winit 0.30.13`. wgpu 27 requires rustc 1.88, so the resolver
  stops at 26; do not raise the floor without a decision recorded in the spec.
- The rig under `refs/` is git-ignored: Temurin JRE 8, an offline-mode 1.8.9 server on port 25565
  (seed `oxidecraft`, level `parity`, spawn protection off), a Prism instance for the vanilla client,
  and the evidence directory with the capture and run logs.

**Commands worth knowing**

```bash
# Full local gate
cargo test --workspace
cargo fmt --all --check

cargo deny check
bash scripts/check-assets.sh

# Launcher
cargo run -p oxide-launcher -- ping 127.0.0.1:25565
cargo run -p oxide-launcher -- fetch --version 1.8.9 --verify    # store lives in the XDG data dir

# Client window (short runs during development)
cargo run -p oxide-client -- --frames 300

# Rig
refs/rig/start.sh ; refs/rig/status_ping.py ; refs/rig/stop.sh
```

**What M1 is.** Spec section 13 defines it as "Bytes to world": protocol framing, handshake, status
ping, offline login, compression, keepalive, the five connection obligations, Join Game, Client
Settings, chunk parsing with both 0x21 and 0x26 verified against a live capture, the world store, and
untextured terrain. The exit criterion is: connect to the test server and see correct world geometry
above y=128 as well as below, with block colours and an F3-style overlay.

**Carried into M1 from the M0 close-out**

- Wrap the connection in a buffered writer; the VarInt path currently issues one write per byte.
- Confirm `Map Chunk Bulk` (0x26) emission against a live capture before relying on it.
- Keep the framing suite as the seed corpus for the fuzz run that M9 requires.
- The guards have no negative self-test yet; add one.
- The frame counter counts only presented frames — the M2 baseline depends on that staying true.
- Store path builders validate their components now; keep passing already-normalised ids.
