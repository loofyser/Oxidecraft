## The mesh core's settled shape (Task 9 extends it)

`build_section_mesh(snapshot: &ColumnSnapshot, sy: usize, ctx: &MeshContext) -> Option<ChunkMesh>`
and `build_column_meshes(snapshot, ctx)`; `ChunkMesh` is still M1's single buffer and Task 9 splits it
into the three layers. `MeshContext` carries `models`, `atlas`, `tint_maps`, `graphics_fast` (carried
unused so far — Task 9's leaves rule is the first consumer) and `smooth_lighting`.

Per quad the mesher: skips it when the neighbour through the declared `cullface` occludes (the table's
`occludes` column, i.e. the source's `isOpaqueCube()`, not `isFullCube()`); takes the light of every
vertex from one sample (the neighbour the face looks into, or the block's own cell for a quad with no
face) unless the block emits nothing, the model's `ambientocclusion` is on and the setting is not off,
in which case the ambient-occlusion path samples four cells per vertex — the quad-bounds base cell
(`fillQuadBounds`'s flags 0 and 1), both combination branches, the `0 → fourth` substitution in
`getAoBrightness` — and multiplies the colour by the four cells' `getAmbientOcclusionLightValue()`
mean; `Minimum` and `Maximum` are the same path in 1.8.9. The colour is the quantised face-shade byte
times the tint bytes (only for quads whose model face carries a tint index), truncated per channel.
The variant choice is position-based (`abs((hash as i32) >> 16) % total_weight` over the
weight-descending, quad-count-ascending list). An unresolved id draws the atlas's fallback sprite and
is logged once from `BlockModelSet::load`. The AO derivation, the cull rule, the variant rule and the
tint confirmation are in `task-8-report.md` §4, each with `File.java:line` citations.

Known interim state: water and glass draw in the single opaque buffer until Task 9 splits the layers;
the fragment stage is still untextured until Tasks 10–11; a session created without assets meshes the
fallback and logs once (the shipping client does this until Task 14's bootstrap); the emission floor
uses the table's per-id value, so a state-dependent light value would be Task 5's table contract. The
plan's known limits 11–13 (the cull rule's own-bounds and same-block-similarity clauses, the
cross-model light sample, the snapshot's out-of-range reads) are the milestone's declared divergences.

## How the work runs

One task at a time, in plan order. For each task: extract its text from the plan into
`task-N-brief.md`, carry it out following the plan's steps and the Global Constraints, record the
report as `task-N-report.md`, freeze the task's diff, have that diff reviewed independently as
`task-N-review.md`, fix and re-review when findings require it, and append one line per event to the
ledger. All of it lives in the local scratch space (git-ignored). The ledger is the recovery map: after any interruption, trust the ledger and
`git log` over recollection, and never redo a task it marks complete.
